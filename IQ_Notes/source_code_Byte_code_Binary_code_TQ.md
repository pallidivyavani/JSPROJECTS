# Source Code, Bytecode, Binary Code — Example (Helloworld.js)

This file compares source code, bytecode, and binary (machine) code using the example from `Helloworld.js` which contains:

```js
console.log("hello world");
```

| Term | What it is | Example (from Helloworld.js) | Produced by / Run on |
|---|---:|---|---|
| Source code | Human-readable program text written by developers. | `console.log("hello world");` | Written by developer; fed to parser/compiler. |
| Bytecode (intermediate) | Compact, VM-specific instructions (interpreted or fed to JIT). Portable only within the same VM. | Pseudo-bytecode (V8-style): `LdaGlobal "console"; GetProperty "log"; Call; ReturnUndefined` | Generated by the engine's bytecode generator (e.g., V8 Ignition); executed by the VM interpreter. |
| Binary / Machine code | Native CPU instructions executed directly by the processor. Fastest, not human-readable. | Pseudo-assembly (x86_64): `mov rdi, <addr>; call <printf>; ret` — the exact output depends on the JIT/AOT compiler and CPU. | Produced by a compiler/JIT (e.g., V8 TurboFan) or an ahead-of-time toolchain; executed on the CPU. |

**Typical pipeline (simplified)**

Source code -> Parser -> AST -> Bytecode -> Interpreter (VM) -> JIT -> Machine code -> CPU

**Commands to inspect (Node / V8 examples)**

- View source: open `Helloworld.js`.
- Print V8 bytecode (approx): `node --print-bytecode Helloworld.js`.
- Print optimized native code (advanced): `node --print-opt-code Helloworld.js` (requires appropriate flags and V8 build).

**Notes**

- "Bytecode" is an implementation detail of a VM (different engines produce different bytecodes).
- "Binary/machine code" is what actually runs on the processor; in many modern runtimes this is produced at runtime by a JIT compiler.
- For interpreted languages, some runtimes only use bytecode (no heavy JIT); others use both interpreter + JIT for hot code paths.
